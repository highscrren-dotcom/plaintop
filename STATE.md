# Состояние проекта

Обновлено: **2026-10-22**. Ветка порта влита в `main` слиянием; дальше всё в `main`. Сделаны
бюджет простоя (решение 18), **частоты всех модулей как настройки, читаемые на лету**,
пресеты спектра и починка **захвата звука** (в службе не было `soundcard`). Подробности — две
верхние записи `docs/JOURNAL.md`; почему так — `DECISIONS.md` (18); грабли — `GOTCHAS.md`, часть III.

## Где мы

- **Plasma — по поведению без изменений**: пять виджетов работают. Из общих файлов правились
  только `MonitorData.qml` (`case "winget"`), `CalendarView.qml`/`Sticker.qml` (`h["public"]`)
  и `notes.py` (пути и `webbrowser` для Windows). Стенды Plasma и job `no-qt` зелёные.
- **Windows — порт в `main` и впервые запущен на живой машине**: пять окон и трей в **одном
  процессе** (`shell.qml`, `oneProcess`), окна создаются по `GET /ui`. Обход процессов —
  нативным вызовом (`NtQuerySystemInformation`: **10 мс против 1531** у psutil), гейты по
  видимости и спросу, доказательство — `GET /perf` и `win/perf.py`.
- **Замеры** (машина 28 потоков, 370 процессов): служба **0,62 % ядра / 58 МиБ** в простое
  (скрытая — 0,31 %), пять окон в одном движке **3,5 % / 166 МиБ** против 532 МиБ «процесс на
  виджет»; вся семья в тишине ~4,7 % / 247 МиБ. **Бюджет 0,5 % не достигнут: потолок — окна.**
- **Частоты — настройки и работают без перезапуска** (`settings_store.LiveSettings`): монитор →
  «Обновления» (`Interval`, процессы **от 1 с**) и «Частоты службы» (датчики/сеть/GPU/
  температуры); спектр → «Производительность» (тихо / сбалансированно / плавно / своё).
  Проверено: `processInterval` 1 → 10 обходов за 10 тиков; `dataRate` 6 → `fps` 20,0 → 6,0.
- **Звук спектра** требует `soundcard` или `pyaudiowpatch` (в zip из CI есть). Захват берёт
  выход по умолчанию и перебирает выходы сам; `GET /devices` — пик по каждому. Окно времени кадров
  в захвате починено (живая частота — float, срез был по float: поток падал каждую секунду при
  музыке дольше десяти секунд — журнал, запись 22.10 «позже»).
- **Стенды**: `win_service` **308**, `win_bands` **75**, `win_media` 94, хосты 9/9 + настройки
  (новые ключи и пресет), `notes.py` 145, `--check-notes`/`--check-relay`. Локально — через
  `uv`-Python 3.12.15; QML — `pyside6-qmllint` (0 ошибок) и живой запуск страниц настроек.
- **Документы**: `win/PROTOCOL.md`, `win/README` EN/RU, решение 18 EN/RU, **27 граблей** в
  части III (EN/RU), журнал.

## Открытые вопросы

- Бюджет ≤0,5 %: нужна работа по перерисовке окон (журнал 21–22.10), не служба.
- Умолчания, которые могут не понравиться: `oneProcess` (вкл) и `smoothMs: 0`. Откат —
  `oneProcess=false` и пресет «Плавно». У кого уже стоит `smoothMs = 70`, пресет покажет «Своё».
- Оболочка `shell.qml` показана только на PySide6-лаунчере, не на настоящем `qml.exe`.
- Google в календаре: свои client id/secret у каждого — приемлемо ли для магазина.
- Windows: имена праздников `holidays` против KHolidays (21 из 29); погода через `/fetch` при
  PAC-прокси; две карты NVIDIA с одним именем.

## Что уже решено, не пересматривать без причины

- Plasma (1–16, `DECISIONS.md`): движок — плазмоид, данные — ksystemstats, погода из QML,
  переводы ki18n, клики отпускает сам плазмоид.
- Windows (17): общие файлы не трогать — шимы `org.kde.*`; одна служба, она же владелец
  настроек и процессов; без C++; Qt 6.8+; токен и отказ по `Origin`.
- Потребление (18): один движок QML с откатом; нативный список процессов с откатом; ничего не
  читать, что никто не видит; **частота — настройка, которую служба читает на лету**.
- Чужие ветки вливаются слиянием, локальные коммиты не переписываются; никогда не `pkill -f`;
  звук для проверок — null-sink; CI без Qt блокирующий.
