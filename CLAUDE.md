# CLAUDE.md — plaintop

Текстовый монитор системы на рабочем столе. Стиль — от Rainmeter-скина PlainExt.
Машина разработки и единственная целевая — `s1dPC` (CachyOS, KDE Plasma 6.7, KWin Wayland).

## «Продолжаем» — полный подхват проекта

Слово **«продолжаем»** (или «продолжим») в начале сессии запускает порядок из
`docs/WORKFLOW.md`, без напоминаний:

1. Прочитать **`STATE.md`** — где проект и какой следующий шаг.
2. Прочитать **последнюю** запись `docs/JOURNAL.md` — с чем столкнулись в прошлый раз.
3. `git log --oneline -10` и `git status`.
4. **Проверить состояние исполнением** — `./install.sh --status` и что требует задача.
   Документ мог отстать от факта; факт главнее.
5. Доложить в нескольких строках, где проект и что предлагается делать — и начать.

Слово **«закрываем»** (или когда контекста осталось мало) запускает закрытие сессии:
проверить исполнением → перезаписать `STATE.md` → дописать запись в `JOURNAL.md` →
закоммитить и запушить → сказать, чем продолжать.
⚠️ Незакоммиченная работа для следующей сессии не существует.

**Проект ведёт основная сессия; исследуют и строят агенты.** Разведку незнакомого API
и независимые куски работы отдавать агентам — они возвращают вывод, а не дампы файлов.
Решения о направлении, запись в журнал и коммиты — только основная сессия.
Подробнее — `docs/WORKFLOW.md`.

## Каталоги

- **`plasmoid/`** — **целевая** реализация: собственный плазмоид Plasma 6 на QML.
- **`conky/`** — первая реализация, работает сейчас, остаётся до замены.
  **Источник истины именно здесь**, не в `~/.config/conky/`: туда файлы попадают
  через `./install.sh`. Правишь тут, затем раскладываешь.
- **`schema/`** — декларативное описание виджета (`widget.json`) и словарь блоков.
  **От движка не зависит** — в этом весь смысл слоя.
- **`STATE.md`** (в корне) — где проект сейчас. Перезаписывается каждую сессию.
- **`docs/JOURNAL.md`** — по записи на сессию, новые сверху. Только дописывается.
- **`docs/WORKFLOW.md`** — метод работы: роли, журнал, закрытие и подхват сессии.
- **`docs/DECISIONS.md`** — решения с обоснованием. Почему плазмоид, а не conky.
- **`docs/GOTCHAS.md`** — разбор граблей. **Читать до правки конфигов conky.**

⚠️ Движок выбран — **плазмоид**. Не развивать conky-реализацию сверх необходимого:
она доживает до замены. Новое поведение делать в `plasmoid/`.

## Разделение владения с setup_machine

⚠️ Репозиторий `~/dev/setup_machine` **больше не снапшотит** `~/.config/conky/*` — владелец
этих файлов здесь. Два писателя на один файл молча разъезжаются; в `setup_machine` остался
только указатель на этот проект. Не возвращать туда `cp ~/.config/conky/...`.

## Команды

| Что | Команда | Готча |
|---|---|---|
| Разложить и запустить | `./install.sh` | перезапускает conky; старые экземпляры гасит |
| Что сейчас работает | `./install.sh --status` | процессы, окно, область ввода |
| Проверить click-through | `./install.sh --check-input` | читает input-shape из X, а не «на глаз» |

## Запреты

- **Никогда не проверять click-through через `xdotool mousemove`** — под Wayland
  синтетические движения мыши блокируются, тест молча показывает не то окно.
  Только чтение input-области из X.
- **Никогда не `pkill -f 'conky -c'`** — шаблон совпадает с командной строкой собственной
  оболочки и убивает её. Только `pkill -x conky`.
- **Никогда не чистить конфиги фильтром по слову.** Удаление всех строк со словом `conky`
  из `ksmserverrc` однажды снесло заодно `excludeApps=conky` — защиту, поставленную строкой
  выше. Правки точечные.
- **Никогда не брать датчики по индексу `hwmon`** — индексы плавают между перезагрузками.
  Только по имени чипа (`coretemp-isa-0000`, `nct6779-isa-0a20`).
- **Никогда не писать в документ непроверенное.** Состояние подтверждается исполнением.
  Прецедент: в этом проекте трижды подряд записывалось «под KWin не работает» про вещи,
  которые работали — просто не были проверены.

## Правило про запуск conky

Запускающих больше, чем кажется: пакетный `conky.desktop`, сессия KWin, сессия ksmserver,
свой автозапуск. Перечислить их заранее нельзя — каждый всплывает после очередной
перезагрузки. Поэтому **операции делаются идемпотентными**: запуск условный, нужное
состояние применяется всегда, кем бы conky ни был поднят. Подробности — `docs/GOTCHAS.md`.
