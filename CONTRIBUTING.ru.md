# Участие в plaintop

[English](CONTRIBUTING.md) · Русский

Форки — это и есть смысл. Проект начинался как личная панель на рабочем столе, и то, что
оказалось полезным всем — слой описания блоков, список ловушек KDE/Wayland — стоит больше
в чужих руках, чем в приватном репозитории. Берите, переделывайте и присылайте обратно
то, что считаете нужным остальным.

## Единственное правило: подтверждать запуском

**Утверждение о поведении — гипотеза, пока оно не исполнено.** Не «в документации
написано», не «должно работать», не «в прошлый раз работало». Запусти, прочитай вывод
целиком, потом записывай.

Правило не для красоты. В журнале проекта записаны три подряд случая, когда «под KWin
не работает» было сказано про вещи, которые работали прекрасно — их просто не пробовали.
Каждая строка в [docs/GOTCHAS.ru.md](docs/GOTCHAS.ru.md) была исполнена на живой системе
до того, как попала в документ.

Поэтому: пул-реквест, меняющий поведение, говорит **что было запущено и что получилось**.
Строчка воспроизведения весит больше абзаца рассуждений.

## Что заходит особенно хорошо

| Вклад | Почему здесь это просто |
|---|---|
| **Новый тип блока** | одна запись в `schema/blocks.json` + один `case` в `monitor/shared/MonitorData.qml`; страницы настроек строятся по словарю сами |
| **Генератор для другого движка** | слой описания намеренно не зависит от движка — waybar, eww, AGS или снова conky |
| **Переносимость на другое железо и дистрибутивы** | значения по умолчанию описывают одну машину; каждый зашитый id датчика, заменённый на поиск, — польза |
| **Ловушка, на которую вы наткнулись** | пул-реквест в `docs/GOTCHAS.ru.md` со способом воспроизведения ценится не меньше кода |
| **Перевод** | все четыре виджета говорят через каталоги gettext в `po/`: новый язык — одна команда и файл `.po`, см. [Переводы](#переводы) |

Прежде чем заводить тип блока, проверьте, не хватает ли открытых: `command` запускает
любую команду со своим интервалом, `sensor` показывает любой датчик `ksystemstats` по id.
Ни одному из них код не нужен — достаточно строки в описании.

## Что где лежит

| Путь | Что там |
|---|---|
| `monitor/package/` | текстовый монитор как виджет Plasma 6: QML, схема настроек, страницы диалога, скрипт служб |
| `monitor/shared/` | данные и рендерер монитора, при установке копируются в пакет |
| `monitor/window/` | бывший оконный хост монитора и его редактор — погашен (решение 9), лежит для справки |
| `monitor/generate.py` | описание → JS-модуль в пакете; проверяет прежде чем писать |
| `schema/widget.json` | раскладка по умолчанию: какие блоки, в каком порядке, с чем |
| `schema/blocks.json` | словарь типов блоков и их параметров |
| `spectrum/package/` | визуализатор звука как виджет Plasma 6, со своей страницей настроек |
| `spectrum/shared/` | рендерер визуализатора — один на кольцо, дугу и линию — копируется в пакет |
| `spectrum/window/` | бывший оконный хост визуализатора и его редактор — погашен (решение 9), лежит для справки |
| `spectrum/relay.py` | полосы cava по локальному HTTP, работает службой systemd; визуализатор читает его |
| `player/package/` | виджет «сейчас играет»: виджет Plasma 6 поверх штатной модели MPRIS Plasma — без общих файлов и без службы |
| `weather/package/` | виджет погоды: виджет Plasma 6, который сам спрашивает Open-Meteo по https — без общих файлов и без службы |
| `po/` | каталоги переводов, по домену на виджет, всего четыре; `extract.py` обновляет их и заводит недостающий, `build.py` собирает |
| `conky/` | первая реализация; заморожена и погашена, живёт до замены плазмоидом |
| `install.sh` | установка, состояние, сборка `.plasmoid`, conky и клики вкл/выкл — все операции идемпотентны |
| `docs/` | грабли, решения, метод работы, журнал сессий, тексты для KDE Store |

Генерируются и в git не хранятся: `monitor/package/contents/code/description.js` (правьте
`schema/*.json`), `contents/locale/` в пакетах (правьте `po/`), `dist/`.

## Цикл разработки

```bash
/usr/lib/qt6/bin/qmllint -I /usr/lib/qt6/qml monitor/package/contents/ui/main.qml   # до установки — именно из Qt 6
./install.sh --plasmoid                                             # сгенерировать + поставить + перезапустить оболочку
./install.sh --spectrum                                             # визуализатор: виджет + служба реле
./install.sh --player                                               # плеер
./install.sh --weather                                              # погода
journalctl --user -b --since "-1min" | grep -i plaintop             # ошибки QML приходят сюда
./install.sh --status                                               # что установлено и что работает
./install.sh --pack                                                 # файлы .plasmoid для релиза → dist/
```

Четыре вещи, которые иначе съедят вам вечер — все четыре разобраны в
[docs/GOTCHAS.ru.md](docs/GOTCHAS.ru.md) с доказательствами:

- **`plasmashell` держит QML пакета в кэше.** Переустановки мало, пересоздания виджета
  тоже. `--plasmoid` перезапускает оболочку за вас.
- **Qt отправляет логи QML в journald, а не в stderr.** Для отдельных проб на `qml6`
  нужен `QT_FORCE_STDERR_LOGGING=1`, иначе кажется, что код вообще не выполнялся.
- **systemd ограничивает частоту перезапусков.** После нескольких подряд получите
  «start request repeated too quickly» и рабочий стол без панели. Лечится
  `systemctl --user reset-failed plasma-plasmashell.service`, затем `start`.
- **`/usr/bin/qmllint` — от Qt 5**, как и `/usr/bin/qml` с `qmltestrunner`. На синтаксисе
  Qt 6 он ничего не печатает и выходит с кодом 255, так что проверка, не глядящая на код
  возврата, проходит. Инструменты Qt 6 лежат в `/usr/lib/qt6/bin/`.

## Новый тип блока, от начала до конца

1. **Словарь** — запись в `schema/blocks.json`:

   ```json
   "fan": {
     "name": "Fan",
     "hint": "One fan by sensor id",
     "params": {
       "label": { "type": "string", "name": "Label", "default": "FAN" },
       "id":    { "type": "string", "name": "Sensor id", "default": "lmsensors/nct6779-isa-0a20/fan1" }
     }
   }
   ```

   Типы параметров: `bool`, `int` (можно `min`/`max`), `string`, `stringlist`. Остальное
   генератор отвергнет, а страница настроек рисует редактор под каждый тип. Имена и
   подсказки — английские исходные строки: `python3 po/extract.py` кладёт их в каталоги,
   а редакторы переводят их там, где показывают.

2. **Раскладка по умолчанию** — при желании добавьте блок в `schema/widget.json`.
   Пользователь и так может добавить его из настроек.

3. **Отрисовка** — один `case` в сборщике строк в `monitor/shared/MonitorData.qml`,
   общем для обоих хостов. Каждое слово, которое он показывает, идёт через `tr.i18n()`:

   ```js
   case "fan": {
       const rpm = num(p.id, 0)
       out.push(kvLine(p.label || "FAN", Math.round(rpm) + " rpm"))
       break
   }
   ```

   Если блок читает датчик, его id должен ещё попасть в подписку — посмотрите, как
   `customSensorIds` собирает id из описания.

4. **Запустите.** `./install.sh --plasmoid`, посмотрите на виджет, проверьте журнал.
   И напишите в пул-реквесте, что увидели.

Генератор править не нужно: проверка идёт по словарю.

## Новый виджет

Плеер и погода добавлены именно так; копируйте тот, что ближе к вашему.

1. **Пакет** — `<имя>/package/`: `metadata.json` (id `org.s1dd1.plain<имя>`, категория,
   версия), `contents/config/main.xml` и `config.qml` (схема настроек и её страницы),
   `contents/ui/main.qml` — хост: размер через `Layout.*` на корне, постоянный для данных
   настроек, и две привязки сквозных кликов, скопированные как есть (решение 8), — и рядом
   вью со строками и отрисовкой. Строки — через `i18n()`.
2. **`install.sh`** — переменные `<ИМЯ>_ID` / `_SRC` / `_DEST`, `<имя>_prepare` (каталоги),
   `<имя>_install` и `<имя>_status`, источник в списке в `pack()`, вызов в `status`, ключ
   `--<имя>` в `case` и в строке usage.
3. **`po/extract.py`** — запись в `DOMAINS`; `python3 po/extract.py` затем пишет шаблон и
   каталог для каждого языка проекта.
4. **README** — строка в таблице каталогов, строка установки, абзац; то же в
   `README.md`.
5. **Запустите** — `./install.sh --<имя>`, посмотрите на стол, прочитайте журнал, напишите
   в пул-реквесте, что увидели.

## Переводы

Виджеты переводятся штатным ki18n из KDE с каталогами gettext, по домену на виджет —
`plasma_applet_org.s1dd1.plaintop` у монитора, `plasma_applet_org.s1dd1.plainspectrum` у
визуализатора, `plasma_applet_org.s1dd1.plainplayer` у плеера,
`plasma_applet_org.s1dd1.plainweather` у погоды. Язык — тот, что в Plasma («Параметры
системы → Язык и регион»); даты и десятичный разделитель следуют её «Форматам». Почему
так и чем за это платим — `docs/DECISIONS.ru.md`, решение 7. В `po/` десять языков; всё,
кроме английского (исходного) и русского, — машинный перевод, ждущий носителя языка:
вычитка готового ценится так же, как новый язык.

```bash
python3 po/extract.py            # обновить po/*.pot по исходникам и влить во все языки
python3 po/extract.py --init uk  # завести новый язык
lokalize po/uk/plasma_applet_org.s1dd1.plaintop.po   # или Poedit, или любой редактор .po
./install.sh --plasmoid          # соберёт .mo монитора в его пакет
./install.sh --spectrum          # то же для визуализатора
./install.sh --player            # … для плеера
./install.sh --weather           # … для погоды
```

`extract.py` заводит и недостающее: новый домен получает каталог в каждом языке, который у
проекта уже есть, через `msginit`. ⚠️ Две вещи до перевода влитого каталога. `msgmerge`
заполняет его «неточными» догадками — старыми переводами, пристёгнутыми к новым строкам, —
которые во время работы пропускаются и сбивают переводчика; сначала снять их:
`msgattrib --clear-fuzzy --empty -o file.po file.po`. А в каталоге, который `msginit`
написал для китайского, стоит `Plural-Forms: nplurals=INTEGER`, и `msgfmt --check` его
отвергает — заголовок поправить руками (`docs/GOTCHAS.ru.md`).

Правила для исходных строк:

- **Они английские.** Русский — такой же перевод, как остальные.
- **Подстановки — `%1`, `%2`**, а не строка, склеенная с числом: "shown %1 of %2", а не
  `"shown " + a + " of " + b`. Переводчику нужна фраза целиком.
- **Число с существительным — через вызов с множественным числом**, `i18np` / `i18ncp`: у
  русского, украинского и польского три формы, и выбирают их правила самого каталога.
- **Где слово двусмысленно — давайте контекст**: `i18nc("palette: colour of", "Header:")`.
- **Файлы, которые грузит только плазмоид, вызывают `i18n()`**; общий QML в
  `monitor/shared/` и `spectrum/shared/` — `tr.i18n()` через `KI18nContext`: привычка от
  погашенных оконных хостов, у голого `qml6` которых своего `i18n()` не было.
- **Ключи не переводятся**: id датчиков, ключи настроек, id блоков.
- **Пункты меню и автозапуска**, которые писал `setup.py` погашенных оконных хостов,
  помечены `N_(контекст, текст)`; строки живут в каталогах, пока живёт код.

`msgfmt --check` идёт при каждой установке, так что перевод, потерявший `%1`, падает там, а
не на экране. Чтобы посмотреть виджет на другом языке, не меняя свой, запустите его
окном: `LANGUAGE=de plasmawindowed org.s1dd1.plaintop`. Чтобы и даты с числами были этой
локали, задайте её в `LANG`/`LC_ALL` и дайте пустой `XDG_CONFIG_HOME`: KDE накладывает
ваши «Форматы» поверх `LANG`. ⚠️ Локаль должна быть сгенерирована
(`locale -a`), иначе gettext откатится на C и покажет английский — без root помогут
`localedef -i de_DE -f UTF-8 $DIR/de_DE.UTF-8` и `LOCPATH=$DIR` (см. `docs/GOTCHAS.ru.md`).

## Стиль

- **Комментарий объясняет почему, а не что.** Код и так читается; а вот причина, по
  которой он такой, обычно нет.
- **Никаких непроверенных утверждений в документах.** Если можно исполнить — исполни.
- **Форматируйте числа сами.** `formattedValue` и `Formatter` вставляют U+200B перед «%»
  и U+2009 перед «°C»; в моноширинных колонках это видно сразу.
- **Чипы `lm_sensors` — по имени**, а не по индексу `hwmon`: индексы плавают между
  перезагрузками.
- **Новое правило сначала становится проверкой.** Если правило может жить в `install.sh`
  проверкой — ему там и место, а не в документе.
- **Комментарии — по-английски, исходные строки для пользователя — тоже** — через
  каталоги, см. [Переводы](#переводы). Вывод в терминале — `install.sh`, скрипты
  установки, генератор — простой английский и не переводится: его читает тот, кто
  ставит из репозитория.

## Коммиты и пул-реквесты

- Один коммит на одну мысль, в теле — **почему** и **что подтверждено запуском**.
  Форму видно в `git log`.
- Для новых коммитов предпочтителен английский; существующая история русская.
- Шаблона для issue нет. «Вот что я запустил, вот что получилось, вот чего ожидал» —
  достаточно.
