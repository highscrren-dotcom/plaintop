# Проверка на ПК: календарь, каналы спектра, монитор 0.4

Инструкция для сессии на s1dPC. Всё ниже написано 2026-10-04 в облачном контейнере без Qt,
Plasma, gettext и cava: код прошёл только то, что можно было исполнить на Python и node.
Здесь — что запустить, в каком порядке, что ожидать и что делать при отказе. Когда всё
пройдено — итоги в `docs/JOURNAL.md` и `STATE.md`, а этот файл удалить: он одноразовый.

Ветка `claude/sleepy-hopper-pzxp2i`, пять коммитов поверх `main`:

|---|---|
| bd8ae39 | Календарь `plaincalendar` 0.1 — новый виджет |
| dd21a63 | Спектр 0.4: опция «Каналы» (`monoSpectrum`), свёртка стерео в реле, интерполяция в `resample` |
| 80dd477 | Реле: `noise_reduction` перенесён в `[smoothing]` |
| 5887626 | Монитор 0.4: исправления, пороги, спарклайны, десять блоков, страница «Блоки», вторая колонка, стенд |

## Перед началом

1. Прочитать `STATE.md`, последнюю запись `docs/JOURNAL.md`, `docs/WORKFLOW.ru.md` (метод) и в
   `docs/GOTCHAS.ru.md` разделы «plasmashell держит QML пакета в кэше», «Логи Qt уходят в
   journald», «systemd глушит plasmashell после частых перезапусков», «`/usr/bin/qmllint` —
   тоже от Qt 5».
2. `git fetch origin && git checkout claude/sleepy-hopper-pzxp2i && git log --oneline -6`.
3. Правило проекта: утверждение о поведении подтверждается запуском, а не чтением. Каждый
   шаг ниже заканчивается выводом команды; вывод — в журнал, не пересказ.
4. Инструменты Qt 6 — `/usr/lib/qt6/bin/`; `/usr/bin/qmllint`, `qml`, `qmltestrunner` — Qt 5 и
   молча врут. Для `qml6` и `qmltestrunner` ставить `QT_FORCE_STDERR_LOGGING=1`.
5. `plasmashell` перезапускать не чаще раза в минуту; после «start request repeated too
   quickly» — `systemctl --user reset-failed plasma-plasmashell.service` и `start`.
6. Никогда не `pkill -f`. Не отключать и не ослаблять тесты ради зелёного.

## Шаг 1 — статика: qmllint

```bash
L=/usr/lib/qt6/bin/qmllint; I=/usr/lib/qt6/qml
$L -I $I calendar/package/contents/ui/main.qml calendar/package/contents/ui/CalendarView.qml \
        calendar/package/contents/ui/configGeneral.qml calendar/package/contents/ui/configMouse.qml
$L -I $I spectrum/shared/Spectrum.qml spectrum/package/contents/ui/configGeneral.qml
./install.sh --plasmoid >/dev/null 2>&1 || true   # кладёт копии shared/*.qml в пакет — иначе qmllint не найдёт типы
$L -I $I monitor/package/contents/ui/main.qml monitor/package/contents/ui/MonitorData.qml \
        monitor/package/contents/ui/MonitorView.qml monitor/package/contents/ui/configBlocks.qml \
        monitor/package/contents/ui/configGeneral.qml
echo "exit $?"
```

Ожидание: код возврата 0, без `error`. Предупреждения вида «unqualified access» в этом
проекте терпимы, если они и раньше были в соседних файлах; новые ошибки — чинить в
`monitor/shared/`, `spectrum/shared/` или `*/package/contents/ui/`, не в копиях.

⚠️ `--plasmoid` на этом шаге уже перезапустил оболочку. Если не хочется — скопировать
руками: `cp monitor/shared/*.qml monitor/package/contents/ui/ && python3 monitor/generate.py`.

## Шаг 2 — стенд строк монитора

```bash
./install.sh --check-monitor
```

Ожидание: `Totals: 15 passed`. Стенд `tests/monitor.qml` **ни разу не запускался**: падение —
вопрос, кто неправ, стенд или виджет. Где стенд опирается на догадки:

- `initTestCase` ждёт 1,5 с, пока `once`-источники (`lscpu`, cpulist, DMI) отработают, потом
  подменяет `nodeCpus`, `cpuModel`, `coreCount`. Если тест 01/02 видит чужие узлы — ждать
  больше или подменять позже.
- `monitor.registry.poll.running = false` — `poll` объявлен как `property var poll: Timer`.
  Если свойство не достаётся, остановить иначе (например, `registry.poll.interval = 1e9`).
- `liveSensors: false` выключает `Instantiator` датчиков, `SensorDataModel` и список
  процессов; значения приходят только через `publish()`. Если значения всё же «живые» —
  смотреть, что ещё пишет в `named`.
- Тест 06 ждёт `AM`/`PM` от `Qt.formatTime(d, "AP")` — локаль C даёт именно их.
- Тест 12 читает `load 2,50` или `load 2.50` — по локали.

Если падает сам виджетный код — это находка: чинить код, тест оставить.

## Шаг 3 — переводы

```bash
python3 po/extract.py && git status --short po/ && git diff --stat po/
for f in po/*/*.po; do printf '%s ' "$f"; msgattrib --untranslated "$f" | grep -c '^msgid' ; done
for f in po/*/*.po; do msgattrib --only-fuzzy "$f" | grep -q '^msgid' && echo "FUZZY: $f"; done
```

Ожидание: `extract.py` перепишет шаблоны и каталоги — меняются только `POT-Creation-Date`,
строки `#:` и перенос длинных строк; **непереведённых 0 и fuzzy нет** (каталоги пяти
доменов писались руками без gettext, и `msgmerge` должен найти в них каждую строку по
`msgid`). Если появились непереведённые — значит, `msgid` в коде и в каталоге разошлись:
исправить каталог, не код. Если fuzzy — `msgattrib --clear-fuzzy --empty`, перевести заново.
`msgfmt --check` идёт при каждой установке и остановит её, если каталог плох.

Коммит после этого шага: «po: catalogs regenerated by extract.py on a machine with gettext».

## Шаг 4 — установка

```bash
./install.sh --spectrum     # переложит relay.py и перезапустит службу — без этого «Каналы» не работают
sleep 2; curl -s 'http://127.0.0.1:8788/bands?bars=16&mono=1'; echo; curl -s http://127.0.0.1:8788/state; echo
journalctl --user -u plainspectrum-relay -n 20 --no-pager
./install.sh --plasmoid     # монитор 0.4
./install.sh --calendar     # новый виджет, сядет на стол
./install.sh --status
journalctl --user -b --since "-3min" --no-pager | grep -iE 'plaintop|plainspectrum|plaincalendar|qml|TypeError|ReferenceError'
```

Ожидание: 16 чисел от `/bands`, в `/state` растут `frames`, статус весь зелёный, в журнале
ни одной ошибки QML от трёх пакетов. ⚠️ Между `--spectrum`, `--plasmoid` и `--calendar` —
по минуте: каждый перезапускает `plasmashell`.

## Шаг 5 — глазами, на столе

**Спектр.** Включить музыку. Кольцо — один спектр от низких (начальный угол) к высоким по
всей окружности, без зеркала. Настройки → «Кольцо» → «Каналы» снять — зеркало вернулось;
поставить — ушло. «Обратный порядок» разворачивает. Сглаживание теперь 60 вместо 77 — кольцо
живее; если дёргается, `PLAINSPECTRUM_NOISE=70` в `~/.config/plainspectrum/relay.env`.

**Календарь.** Три месяца столбиком, `СЕНТЯБРЬ 2026` / `ОКТЯБРЬ 2026` / `НОЯБРЬ 2026`, строка
`пн вт ср чт пт сб вс`, номера недель 36–40, 40–44, 44–49, выходные красным, сегодня в
скобках `[ 4]` синим. Настройки: «один — текущий», неделя с воскресенья, «соседние месяцы»,
ячейка 6 знаков — размер виджета меняется, контейнер не сбрасывает его в угол. ⚠️ Если
вместо названий `undefined` или пусто — `Qt.locale().dayName()`, `standaloneMonthName()` или
`weekDays` в этой версии Qt ведут себя не так, как в документации; см. шаг 6.

**Монитор.** Строка модели: `2x Intel Xeon …  36c/72t  2,8 GHz  62/58°C  …` — два узла на
s1dPC, обе температуры, частота; `S0`/`S1` с `node0`/`node1`. Новые блоки в раскладке по
умолчанию: `нагрузка 0,52  0,61  0,70` под PSI, `SWP` после ОЗУ (если своп есть; без свопа
строк нет), `I/O  Чт … Зп …` после дисков. Пороги: на странице «Блоки» у «Процессор»
поставить «Тревога от» 1 — полоска CPU краснеет, вернуть 90. «История» 20 у CPU — через
20 с после полоски `▁▂▃▅▇…`. Вторая колонка: у «Паспорт железа» колонка «правая» — он уходит
на половину ширины; «Общее» → «Вторая колонка от» двигает. Страница «Блоки»: у «Диски»
список выбора у «Датчик температуры NVMe» показывает `lmsensors/nvme-…`; «Дублировать»
даёт `command2`; «Имя» видно в списке; внизу JSON — испортить скобку, «Применить JSON» даёт
красное сообщение, «Перечитать из списка» возвращает. Добавить блоки и посмотреть строки:
«Юниты systemd» с `plainspectrum-relay.service` и галкой «пользовательские» → `active`;
«Батареи периферии» — мышь/гарнитура с процентами; «Звук» — `VOL` и имя устройства, с
галкой «ввод» ещё `MIC`; «Репозитории git» с `~/plaintop` → ветка и `±N`; «Температуры» с
двумя id из списка выбора, один с `VRM=` → подпись и имя датчика. Строка «Службы»: docker,
pacman (как раньше), а также podman/libvirt, если стоят.

Скриншот стола для журнала: `spectacle -b -n -o ~/Desktop/verify-2026-10-04.png` после
«Show Desktop» (рецепт в `STATE.md`, «Окружение»).

## Шаг 6 — допущения, взятые из документации, а не из запуска

Для каждого — как проверить одной командой и что делать, если не так.

1. **Идентификаторы датчиков** `cpu/loadaverages/loadaverage1|5|15`, `disk/all/read|write`,
   `memory/swap/used|total`, `network/<iface>/ipv4address|totalDownload|totalUpload|signal`,
   `cpu/cpuN/frequency`, `gpu/gpuN/usage`. Список всех id машины:

   ```bash
   cat > /tmp/ids.qml <<'EOF'
   import QtQuick
   import org.kde.ksysguard.sensors as Sensors
   Item {
       property var tree: Sensors.SensorTreeModel {}
       function walk(parent) {
           for (let r = 0; r < tree.rowCount(parent); r++) {
               const idx = tree.index(r, 0, parent)
               const id = tree.data(idx, Sensors.SensorTreeModel.SensorId)
               if (id && !/[(*\\?\[\]|+]/.test(String(id))) console.log(id)
               if (tree.rowCount(idx) > 0) walk(idx)
           }
       }
       Timer { interval: 2000; running: true; onTriggered: { walk(undefined); Qt.quit() } }
   }
   EOF
   QT_FORCE_STDERR_LOGGING=1 QT_QPA_PLATFORM=offscreen /usr/lib/qt6/bin/qml /tmp/ids.qml 2>&1 | grep -E 'loadaverage|disk/|swap|ipv4address|signal|frequency|gpu/' | sort
   ```

   Нет id — блок молчит (так задумано); если id называется иначе, поправить шаблон в
   `MonitorData.qml` (`loadIds`, `diskReadId`, `swapIds`, `netExtraIds`, `gpus`) и записать в
   GOTCHAS, какое имя настоящее.
2. **`Qt.locale().weekDays`, `firstDayOfWeek`, `dayName()`, `standaloneMonthName()`** в
   `CalendarView.qml` — если календарь пуст или с `undefined`, проверить в `qml6`:
   `console.log(Qt.locale().weekDays, Qt.locale().firstDayOfWeek, Qt.locale().dayName(1, Locale.ShortFormat), Qt.locale().standaloneMonthName(10, Locale.LongFormat))`.
3. **Скрипты блоков** — запустить руками из установленного пакета и прочитать вывод:
   `P=~/.local/share/plasma/plasmoids/org.s1dd1.plaintop/contents/code; bash $P/sound.sh input; bash $P/peripherals.sh; bash $P/units.sh --user plainspectrum-relay.service; bash $P/repos.sh ~/plaintop; bash $P/services.sh; bash $P/health.sh 2`.
   Формат `wpctl inspect` (`node.description`) и `upower -i` (`model`, `percentage`,
   `power supply`) взяты по памяти.
4. **`flatpak remote-ls --updates --cached`, выход `dnf -C check-update` 100, `zypper lu`** —
   на Arch не исполняются; оставить как есть, отметить в журнале «не проверено».
5. **Стерео cava** — после шага 5 записать в GOTCHAS (en + ru) как подтверждённое: cava без
   `channels` отдаёт левый канал в обратном порядке, затем правый; и второй пункт — ключ
   `noise_reduction` читается только из `[smoothing]`.

## Шаг 7 — если что-то упало

- Ошибка QML в журнале: `file:line` → правка в репозитории (`monitor/shared/`,
  `calendar/package/contents/ui/`, `spectrum/shared/`), снова `./install.sh --<виджет>`,
  снова журнал. Один коммит на одну причину, в теле — что было запущено и что получилось.
- Падает стенд, а виджет на столе прав — чинить стенд, написать в журнал, почему он ошибался.
- Виджет молчит там, где ждёшь строку — сначала шаг 6, пункт 1: есть ли датчик.
- Диалог настроек не открывается или пуст — журнал; чаще всего опечатка в `cfg_*` или в
  `main.xml`; `qmllint` страницы диалога.
